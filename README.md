[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

create a new feature for the project that follows clean architecture

_Generated by [mason][1] 🧱_

## Overview 🏗️

This brick generates a complete, production-ready feature module following **Clean Architecture** principles with **Riverpod state management**, database caching via **Drift** (SQLite), and dependency injection using **Riverpod**.

## Clean Architecture Layers 🎯

The brick implements a layered architecture with clear separation of concerns. Each layer is independent and communicates through well-defined interfaces.

### 1. Data Layer 💾

**Responsibility:** Handle all data operations—fetching from APIs, storing/retrieving from local database, and data transformation.

**Location:** `data/`

**Components:**

#### Local Datasources (`data/datasources/local/`)

- **DAO (Data Access Objects)**
  - `i_{feature_name}_dao.dart` — Interface defining database operations
  - `{feature_name}_drift_dao.dart` — Drift implementation for SQLite operations
- **Filtering** — Query strategy pattern for advanced filtering
  - `cursor_db_query_strategy.dart` — Pagination using cursor-based navigation
  - `search_db_query_strategy.dart` — Full-text search on local data
  - `cursor_and_search_db_query_strategy.dart` — Combined cursor + search
  - `db_query_strategy_factory.dart` — Factory to create appropriate strategy
- **Sorting** — Database sorting configuration
  - `db_{feature_name}_sort_by.dart` — Sort options (by name, date, etc.)
- **Mappers** — Convert database models to domain entities
  - `table_{feature_name}_mapper.dart` — Map Drift table → cache model
- **Model** — Local cache data structure
  - `{feature_name}_cache_model.dart` — Cached entity representation

#### Remote Datasources (`data/datasources/remote/`)

- **Model** — API response structures
  - `{feature_name}_api_response.dart` — API response data class
- **Implementation**
  - `i_{feature_name}_remote_datasource.dart` — Interface for remote operations
  - `{feature_name}_remote_datasource.dart` — HTTP client implementation
  - `endpoints.dart` — API endpoint URLs and constants

#### Repositories (`data/repositories/`)

- **`i_{feature_name}_repository.dart`** — Repository interface (contract)
- **`{feature_name}_repository.dart`** — Repository implementation
  - Combines local and remote datasources
  - Handles cache-first or network-first strategies
  - Error handling and data transformation

### 2. Domain Layer 🧠

**Responsibility:** Pure business logic, independent of frameworks. Contains entity definitions and use case implementations.

**Location:** `domain/`

**Components:**

#### Entities (`domain/entities/`)

- **`{feature_name}.dart`** — Main entity representing the core business object
- **`add_{feature_name}.dart`** — Request entity for creation operations (parameters)

#### Use Cases (`domain/usecases/`)

Each use case represents a single business operation following the Single Responsibility Principle.

- **Interfaces** (I-prefix)
  - `i_add_{feature_name}_usecase.dart` — Contract for adding/creating
  - `i_get_{feature_name}_usecase.dart` — Contract for fetching a single item
  - `i_get_all_{feature_name}_usecase.dart` — Contract for fetching all items

- **Implementations**
  - `add_{feature_name}_usecase.dart` — Business logic for creation
  - `get_{feature_name}_usecase.dart` — Business logic for single item retrieval
  - `get_all_{feature_name}_usecase.dart` — Business logic for list retrieval

### 3. Presentation Layer 🎨

**Responsibility:** UI rendering and state management. Handles user interactions and displays data.

**Location:** `presentation/`

**Components:**

#### Controllers (`presentation/controllers/`)

- **`{feature_name}_controller.dart`** — Orchestrates data flow between UI and usecases
  - Delegates business logic to usecases
  - Manages feature-level state

#### Notifiers (`presentation/notifiers/`)

State change handlers using Riverpod's `Notifier` pattern:

- **`{feature_name}_data_notifier.dart`** — Manages data state
  - Loading states
  - Success/error states
  - Data updates
- **`{feature_name}_ui_notifier.dart`** — Manages UI state
  - Navigation triggers
  - Dialog/snackbar visibility
  - Form state and validation

#### States (`presentation/states/`)

Immutable state definitions:

- **`{feature_name}_data_state.dart`** — Data state classes (LoadingState, SuccessState, ErrorState)
- **`{feature_name}_ui_state.dart`** — UI state classes (navigation, UI events)

#### Widgets (`presentation/widgets/`)

- **`custom_card.dart`** — Reusable card widget for displaying list items
- Additional custom widgets as needed

#### Screen (`presentation/`)

- **`{feature_name}_screen.dart`** — Main feature screen/page
  - Listens to notifiers for state changes
  - Triggers actions via controller
  - Renders the UI using widgets

### 4. Dependency Injection Layer 🔌

**Responsibility:** Provide instances of repositories, usecases, datasources, and controllers.

**Location:** `providers/`

**Components:**

- **`{feature_name}_datasource_providers.dart`** — Provides local and remote datasource instances
- **`{feature_name}_repositories_providers.dart`** — Provides repository instances
- **`{feature_name}_usecases_providers.dart`** — Provides usecase instances
- All injected via Riverpod providers for dependency management and testing

## Technology Stack 🛠️

- **Architecture:** Clean Architecture with MVVM (Model-View-ViewModel)
- **Database:** [Drift](https://drift.simonbinder.eu/) — Type-safe SQLite ORM
- **Dependency Injection:** [Riverpod](https://riverpod.dev/) — Reactive dependency injection
- **State Management:** Riverpod Notifiers with immutable state classes
- **Language:** Dart with null safety

## Getting Started 🚀

### Prerequisites

Make sure you have Mason installed:

```bash
dart pub global activate mason_cli
```

### Usage

Generate a new feature using this brick:

```bash
mason make feature_brick
```

When prompted, provide:

- **Feature Name** — The name of your feature (e.g., `products`, `users`, `orders`)
- **Project Name** — The name of your Flutter project (e.g., `employee_book`)

The brick will generate a complete feature module with all layers ready to customize.

### Example

```bash
mason make feature_brick
? What is the feature name? products
? What is the project name? my_app
```

This creates the feature structure at `lib/features/products/` with all necessary files.
